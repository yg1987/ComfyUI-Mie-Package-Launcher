# 插件版本管理界面改造计划

## 目标

将“插件版本管理”页面改为可快速浏览、操作有反馈、异常可追溯的管理界面。

页面遵循两条统一规则：

1. 表格只承载需要快速判断的短信息，不将长错误或处理说明挤进单元格。
2. 所有用户操作必须有可见的开始、进行中和结束反馈；需要用户决定或处理的内容必须提供完整、可复制、可滚动的说明，不能用省略号隐藏关键信息。

## 交互设计

### 1. 表格字段

- 移除“版本”列。分支与提交仅用于内部判断，并在状态详情或操作结果中按需展示。
- 保留“来源”列，完整显示 Git 地址并提供点击复制；复制后显示“地址已复制”。
- “操作”列使用固定宽度、明确的按钮最小尺寸和间距，确保“更新”“卸载”等按钮完整可见、可点击。
- 表格状态使用短文本与颜色：
  - 正常：绿色；
  - 可更新：强调色；
  - 需处理：橙色；
  - 异常：红色；
  - 已禁用或未检查：灰色。
- 非正常状态使用可点击文本（或等价的详情入口）。点击后打开“状态详情”窗口。

### 2. 状态详情

状态详情不在表格中铺开。详情窗口完整展示：

- 插件名称、插件目录、来源地址、分支和提交（如有）；
- 当前状态及更新状态；
- 服务返回的完整原因、错误码、依赖冲突与依赖预检结果；
- 针对状态的处理建议，例如处理本地修改、配置远程仓库或上游分支、处理依赖冲突；
- “复制全部信息”操作。

窗口允许滚动和调整大小，长文本不得截断。

### 3. 筛选与空状态

状态筛选精简为：

- 全部；
- 可更新；
- 异常 / 需处理。

筛选无结果时显示明确空状态，不只留下空白表格。

### 4. 操作反馈闭环

所有后台操作使用页内状态区显示开始和进行中状态；需要确认、失败或包含多项结果时使用完整详情弹窗。

| 操作 | 开始与进行中 | 结束反馈 |
| --- | --- | --- |
| 首次扫描 / 刷新 | 显示正在检查 | 显示检查完成摘要；失败显示完整错误详情 |
| 安装插件 | 校验地址并显示预检中 | 确认窗口完整显示来源、目标目录与依赖预检；完成显示结果 |
| 单个更新 | 显示正在更新插件名 | 显示成功、跳过、取消或失败的完整结果 |
| 全部更新 | 显示总数和逐项进度 | 完整汇总每个插件的结果、原因及依赖变更 |
| 无可更新项 | 不静默返回 | 显示检查数量、已最新数量、需处理插件及其详情入口 |
| 卸载插件 | 确认窗口完整显示目录与影响 | 显示卸载成功或失败的完整结果 |

后台控制器已提供逐项进度信号；页面需要连接该信号并在操作结果返回时展示结果，而不是只静默重新扫描列表。

## 实施步骤

1. 重构 `ui_qt/pages/plugin_page.py` 的列定义、筛选逻辑和单元格交互。
2. 增加状态详情与操作结果的可复制、可滚动弹窗组件或复用现有同类组件。
3. 连接任务控制器的进度信号，区分扫描结果与安装、更新、卸载结果，并形成完整反馈闭环。
4. 为刷新、无可更新、状态详情、来源复制、单项更新和批量更新结果增加或更新测试。
5. 在打包环境中运行相关单元测试，并手工检查 100% 缩放下的表格列宽、按钮和长文本详情。

## 验收标准

- 页面不再显示版本列，来源地址能完整获取并复制。
- 操作按钮在常用窗口宽度下文字完整且可点击。
- 任意非正常状态可从表格进入完整详情，详情不截断。
- 点击刷新、安装、单项更新、全部更新、卸载均有开始与结束反馈。
- “全部更新（0）”会解释为什么没有可更新项，不再静默。
- 筛选项仅为“全部 / 可更新 / 异常或需处理”，筛选结果和空状态准确。
