# 自用-软链接功能设计方案

**状态：** 已实现
**目标版本：** v1.0.14
**适用范围：** Windows 版 ComfyUI 启动器，支持多环境

## 1. 背景与目标

ComfyUI 的模型、输入、输出和工作流通常占用大量磁盘空间。用户希望把这些数据放在任意盘符、任意目录中，并在 ComfyUI 原有位置创建目录链接，使 ComfyUI 无需修改配置即可继续使用。

功能入口新增为侧边栏菜单：`自用-软链接`。

本功能不设置“共享根目录”。每一条规则独立配置目标目录，以支持以下两种使用方式：

- 集中管理：例如全部指向 `D:\cmShare` 下的不同子目录；
- 分散管理：例如模型放在 NAS 映射盘，输出放在本地 SSD，工作流放在另一个项目目录。

## 2. 管理范围

每个 ComfyUI 环境可独立设置以下四个目录链接。链接来源始终根据当前环境的 ComfyUI 根目录动态计算，不让用户手填来源路径。

| 标识 | ComfyUI 内来源目录 | 可单独设置的目标目录 | 默认状态 |
| --- | --- | --- | --- |
| `models` | `ComfyUI\models` | 用户选择 | 未启用 |
| `input` | `ComfyUI\input` | 用户选择 | 未启用 |
| `output` | `ComfyUI\output` | 用户选择 | 未启用 |
| `workflows` | `ComfyUI\user\default\workflows` | 用户选择 | 未启用 |

> “工作流”仅指上述默认工作流目录；本功能不修改 ComfyUI 自定义工作流路径或外置模型库配置。

## 3. 页面设计

### 3.1 顶部强制安全提示

页面最顶部使用醒目的警告卡片（警告色、图标和加粗标题），固定放在所有配置项之前：

> ⚠️ **首次创建链接前，请先自行把原文件夹中的模型、图片和工作流移动到目标目录。**
>
> 本功能不会移动、复制或删除你的文件。若 ComfyUI 原目录仍含有文件，系统会拒绝创建链接，以避免误操作导致文件不可见或被误以为丢失。

警告卡片中还应直接列出需检查和迁移的目录（以下路径均相对于 `ComfyUI` 根目录）：

| 用途 | 相对路径 |
| --- | --- |
| 模型 | `models` |
| 输入图片/文件 | `input` |
| 输出图片/文件 | `output` |
| 工作流 | `user\default\workflows` |

提示下方补充简短说明：

- 创建后，ComfyUI 仍使用原路径，但实际数据会写入你选择的目标目录；
- “移除链接”只移除链接本身，绝不删除目标目录中的数据；
- 操作前必须停止 ComfyUI。

### 3.2 环境与规则列表

页面顶部显示当前环境名称和 ComfyUI 根目录，并提供切换环境的入口或提示用户在现有“系统设置”中切换。

每条规则显示：

- 目录名称和来源路径；
- 启用开关；
- 目标目录输入框与“选择目录”按钮；
- 当前状态：未配置、未创建、链接正常、目标不存在、来源为普通目录、链接指向错误、无权限等；
- 操作按钮：`打开来源`、`打开目标`、`创建/修复链接`、`移除链接`。

页面底部提供批量操作：`检查全部`、`创建/修复已启用项`。批量操作逐项展示结果，不因单项失败掩盖其他项状态。

## 4. 配置模型

配置保存于启动器现有 `launcher/config.json`。由于不同 ComfyUI 环境的来源目录不同，规则按环境 ID 存储；同一个目标目录允许被多个环境引用，但页面不强制如此。

示意结构：

```json
{
  "symlink_manager": {
    "environments": {
      "env-id": {
        "models": { "enabled": true, "target_path": "D:\\cmShare\\models" },
        "input": { "enabled": true, "target_path": "D:\\cmShare\\input" },
        "output": { "enabled": true, "target_path": "D:\\cmShare\\output" },
        "workflows": { "enabled": true, "target_path": "D:\\cmShare\\workflows" }
      }
    }
  }
}
```

不保存可变的来源绝对路径，也不保存文件清单；来源路径始终由“当前环境的 `comfyui_root` + 固定相对路径”实时推导，避免切换环境后误操作到另一个安装目录。

## 5. 安全操作规则

### 5.1 创建或修复链接

创建前必须同时满足以下条件：

1. 当前 ComfyUI 已停止；若运行中，拒绝执行并提示先停止。
2. 目标路径已填写；若目标不存在，允许用户明确确认后创建一个**空目标目录**。
3. 来源路径不存在，或来源是可确认的空目录。
4. 来源若已是指向当前目标的目录链接，则不重复创建，直接报告“链接正常”。

以下情况一律不做自动覆盖、删除、移动或复制：

| 来源状态 | 行为 |
| --- | --- |
| 普通目录且含任何文件（包含隐藏文件） | 阻止创建；提示用户手动移动文件到目标目录后重试 |
| 已是目录链接但指向其他路径 | 阻止覆盖；要求用户确认后先“移除链接”，再创建新链接 |
| 普通空目录 | 经明确确认后才移除空目录并创建链接 |
| 目标路径不存在且用户未确认创建 | 不执行 |
| 目标是文件而非目录 | 不执行 |

检查“目录非空”只用于安全拦截，不扫描或展示完整模型文件列表，避免大型模型库导致页面卡顿。

### 5.2 链接类型与权限

界面文案统一称为“目录链接”。实现优先使用 Windows 目录联接（junction，`mklink /J`），因为它适用于本地磁盘跨盘连接且通常不需要管理员权限。

- 本地卷目标：优先目录联接；
- 网络路径或目录联接不支持的场景：尝试目录符号链接；
- 若符号链接因未启用开发者模式或权限不足而失败：展示明确错误和处理说明，不降级为复制目录；
- 状态检查必须能识别目录联接、目录符号链接、断开的链接和普通目录。

### 5.3 移除链接

移除操作同样要求 ComfyUI 已停止，并必须二次确认。只允许删除已识别的目录链接/目录联接：

- 绝不递归删除来源或目标目录；
- 绝不删除目标中的任何模型、图片或工作流；
- 来源不是链接时禁用该操作，避免误删普通目录。

## 6. 更新、重装与自愈策略

### 6.1 当前启动器更新的行为

当前启动器对现有 ComfyUI 目录执行 Git `fetch`、`pull` 或 `checkout`，并非删除后重新克隆整个 `ComfyUI` 文件夹。正常情况下，已存在的未跟踪目录链接会被保留。

若未来上游新增了与链接目录冲突的受 Git 管理文件，Git 通常会报路径冲突并拒绝更新，不会无提示覆盖链接目标中的用户数据。

### 6.2 更新前后检查

为应对异常更新、手动解压覆盖、切换环境或未来上游变化，软链接服务应在以下时机检查已启用规则：

1. 用户在软链接页点击“检查全部”；
2. ComfyUI 内核更新开始前；
3. ComfyUI 内核更新结束后（无论成功或失败均检查）；
4. 用户点击启动 ComfyUI 前。

检查结果分为：

- **正常：** 来源链接指向已配置的目标；
- **可安全修复：** 来源不存在或仅是空普通目录，目标是有效目录；
- **需要人工处理：** 来源变成含文件的普通目录、链接指向其他位置、目标无效、权限不足。

### 6.3 自动修复边界

自动修复仅允许处理“可安全修复”状态：来源不存在或来源为空目录、目标有效、ComfyUI 已停止。此时创建或恢复目录链接，并写入启动器日志。

所有可能涉及已有文件的情况均不自动修复；启动或更新结果中应显示醒目提示和“前往软链接页面处理”入口。这样即使用户不理解目录链接，也不会因为自动操作而丢失或误以为丢失模型。

用户手动整目录重装或解压覆盖 `ComfyUI` 时，原链接可能被移除；下一次启动前检查会识别并在安全条件满足时恢复，或提示人工迁移。

## 7. 运行流程

```text
配置目标目录 → 用户手动迁移原有文件 → 停止 ComfyUI
       ↓
检查来源和目标状态
       ├─ 来源含文件 / 指向错误 / 无权限 → 阻止并说明原因
       └─ 来源不存在或为空、目标有效 → 创建目录链接
                                                ↓
                                      后续启动与更新前后自动检查
                                                ↓
                         正常继续 / 安全修复 / 提醒用户人工处理
```

## 8. 实现划分

| 模块 | 职责 |
| --- | --- |
| 软链接服务 | 路径推导、状态识别、创建、移除、批量检查与安全修复 |
| 软链接页面 | 警告提示、独立路径编辑、状态呈现、用户确认和打开目录 |
| 配置迁移/默认值 | 为已有配置补充空的 `symlink_manager`，不影响旧用户 |
| 应用生命周期接入 | 在更新前后、启动前调用检查服务，并仅执行安全修复 |
| 测试 | 覆盖状态机、数据保护、配置隔离、菜单页面映射与生命周期调用 |

服务层不得依赖 Qt 控件，以便单元测试验证文件系统行为；页面层只负责展示、选择目录和确认交互。

## 9. 验收标准

1. 侧边栏有 `自用-软链接` 菜单，且菜单顺序与页面注册顺序一致。
2. 顶部安全提示在任何分辨率下先于规则列表显示，明确要求用户先手动移动文件。
3. 四项规则均可分别配置、启用、检查、创建、移除和打开目标目录。
4. 已有文件的普通来源目录不能被“创建/修复”操作删除、覆盖或自动迁移。
5. 移除目录链接后，目标目录及其中数据保持完整。
6. 不同 ComfyUI 环境的规则互不覆盖。
7. 正常更新后链接保持有效；异常丢失时能在启动前或更新后被检测到。
8. 仅在来源为空/不存在时自动修复；任何含文件的来源目录均要求人工处理。
9. 无管理员/开发者模式权限、目标路径非法、链接断开和目标不可访问时，界面给出可理解的错误原因。
10. 所有安全分支均有自动化测试，且不对真实用户目录执行递归删除。

## 10. 非目标

- 不自动迁移、复制、合并或删除模型、图片、工作流；
- 不修改 ComfyUI 的外置模型库 YAML 配置；
- 不支持把单个文件替换为链接；
- 不保证第三方手动重装工具保留链接，只负责后续检测与安全恢复。
